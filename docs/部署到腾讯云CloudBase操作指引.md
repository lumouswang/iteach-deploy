## 一、为什么选云托管，而不是云函数

你的项目有 **WebSocket 长连接**（开房间、双人对战、教师端实时同步）。
云函数执行完就释放，长连接会断，**必须用容器类方案**。

| 产品 | 长连接 | 结论 |
|---|---|---|
| 云函数 SCF / 函数计算 FC | ❌ 请求完即释放 | 不可用 |
| **CloudBase 云托管** | ✅ 官方定位就是"需要长连接的场景" | **选它** |

## 四、使用注意

- **首次访问慢**：最小实例数为 0 时，冷启动约 10–30 秒。课堂现场建议提前 1 分钟打开预热。
- **数据不持久**：房间数据在内存，服务重启或缩容到 0 后清空。这符合课堂"单节课用完即弃"的场景。
- **多人同玩**：同一房间链接可多人访问；双人模式需两个设备分别用玩家 A、B 加入。
- **额度查询**：控制台 → 费用中心，可看剩余赠送额度。

## 五、后续更新代码

代码改动后，在本地重新构建前端：

```bash
cd frontend && npm run build
cd .. && rm -rf backend/static && mkdir -p backend/static && cp -r frontend/dist/* backend/static/
```

然后在云托管控制台 → 服务 → **新建版本** → 重新上传代码包 → 发布。

> CloudBase 也支持绑定 Git 仓库自动部署，但需要额外配置，课堂场景手动上传更直接。

## 六、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 部署成功但访问 502 | 监听端口填错 | 确认填的是 `8000`，与 Dockerfile 一致 |
| 页面空白 | 前端未构建进镜像 | 检查 Dockerfile 的 `COPY --from=frontend-builder` 是否成功 |
| 能打开但聊天/对战不通 | WebSocket 被断 | 确认服务是"云托管"而非"云函数" |
| 构建卡住 | 代码包过大 | 确认 `frontend/node_modules`、`backend/.venv` 未被上传（已在 `.dockerignore` 排除） |
| 免费额度快用完 | 最小实例数 > 0 | 改为 0，用前预热 |
